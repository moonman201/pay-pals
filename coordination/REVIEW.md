[2026-10-07] [packages/db] The memory store's saveCard and lockCard never look at the deal state. A BLOCKED deal (or CANCELLED, ISSUE, COMPLETE) still accepts a new card version and still locks it, so the contract comment "Lock the current version. Called once, at AGREED" is not enforced by the store, only by whoever calls it. Repro: createDeal, saveCard v1, transition LISTED, REVIEWED, BLOCKED, then saveCard v2 succeeds and lockCard(id, 2) returns a locked card with deal.lockedCardVersion = 2. The case is in tests/integration/src/verdict-feeds-state-machine.test.ts marked `it.fails` ("refuses to lock the card on a BLOCKED deal"); flip it to `it` once fixed, and the Postgres store should match through the conformance suite. Suggested rule: saveCard only when isCardEditable(deal.state); lockCard only from REVIEWED or AGREED. Owner: builder-paypal.
